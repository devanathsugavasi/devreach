# Launch Checklist

Filter to what applies to the project.

## Before announcing

- [ ] Install/upgrade command tested from a clean environment (new venv, fresh container, or another machine)
- [ ] README quick-start matches the released version
- [ ] Every link in the announcement opens (repo, docs, demo, download)
- [ ] Release notes published (GitHub release, CHANGELOG, or docs)
- [ ] Version number consistent everywhere (package metadata, tag, docs, announcement)
- [ ] Demo video/GIF uploaded and plays without login
- [ ] Known issues listed honestly
- [ ] Screenshots don't show secrets, personal data, or internal tools
- [ ] Issue templates exist so people can report problems

## Launch day

- [ ] Block 2 hours after posting to answer questions
- [ ] Watch the issue tracker for install failures
- [ ] Post in one venue at a time, not everywhere at once
- [ ] Reply to every genuine comment, including critical ones

## After (within a week)

- [ ] Fix the top reported problem and ship a patch release
- [ ] Thank contributors and early testers publicly (with permission)
- [ ] Write down what worked and what didn't for next time (see `growth-review`)
